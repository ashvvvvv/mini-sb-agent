# 内存占用对比：GitHub 最新版 vs 本地修复版

对比日期：2026-09-28。环境：Windows 10 amd64，Go 1.26.4，GOMAXPROCS(1)（程序内部设置）。

- **基线（GitHub 最新）**：`2b57186`（= `origin/master`，即审查报告的基线提交）。
- **修复版**：`2644373`（本地 HEAD：`7a718d5` 六项修复 + `1ee6f1d` 完整身份/退出顺序 + `2644373` struct 键收尾）。
- 两侧均用默认构建（无 build tags）、同一 Go 工具链从源码构建；`go version -m` 确认依赖完全一致，仅源码差异。
- 场景：空闲 agent（空入站、stats API 关闭）+ `-users` 本地用户表（一半有限速、一半无限速），panel 同步循环每 2s 重放；`-debug-runtime-log` 采样 Go heap，PowerShell 采 Windows 工作集。
- 复现脚本：`review/memcmp.sh`（含预热、交替顺序、12s 稳定期、末 5 次采样均值、每场景 3 次试验）。

## 结论

**无实质内存回归。** 空闲与加载场景工作集持平（差异 ≤0.7% 或在噪声内）；唯一可测的常驻增量是 #3 修复为每个用户保留的限速器对，约 **117 B/用户**；goroutine 数在所有场景完全一致；二进制 +8 KB（+0.04%）。

## 数据（3 次试验均值）

### 工作集（Windows WorkingSet，MiB）

| 场景 | 基线 | 修复版 | 差值 |
|---|---:|---:|---:|
| 空闲（默认） | 14.04 | 14.30 | +0.26 |
| 1000 用户（默认） | 16.95 | 16.75 | −0.20（噪声内） |
| 10000 用户（默认） | 28.27 | 28.45 | +0.18 |
| 空闲（强制 GC） | 13.19 | 13.42 | +0.23 |
| 5000 用户（强制 GC） | 18.54 | 19.21 | +0.67 |
| 10000 用户（强制 GC） | 23.06 | 24.41 | +1.35 |

### Go heap 指标

`heap_alloc`/`heap_sys` 在所有场景差异均在 GC 采样噪声内（单次试验摆动 ±0.5 MiB，强制 GC 模式下 10000 用户：9.60 vs 9.21 MiB）。goroutine 数：空闲 4、带同步 5、带 scavenge 6——**两版完全一致**（`Syncer.Start` 的包装 goroutine 就是运行 `Run` 的那个 goroutine，不新增）。

### 每用户斜率（强制 GC 模式工作集）

- 基线：(23.06−13.19) MiB / 10000 用户 ≈ **1034 B/用户**
- 修复版：(24.41−13.42) MiB / 10000 用户 ≈ **1150 B/用户**
- 差值 ≈ **117 B/用户**：即 #3 修复为无限速用户也保留的 `limiterPair`（2×64B `RateLimiter` + 16B pair + map 条目），换取限速热更新不断连。

### 二进制尺寸

- 基线 21,784,576 B；修复版 21,792,768 B；**+8,192 B（+0.04%）**。

## 分析

1. 空闲差 +0.23 MiB（+1.7%）来自二进制布局变化（多 8 KB 代码导致触碰页集合略变），非运行时状态。
2. 每用户 +117 B 是 #3（限速器生命周期）的代价，随用户数线性、有界；1000 用户 ≈ +0.12 MiB，10000 用户 ≈ +1.35 MiB。
3. #2 的 acked map 为每次 flush 的瞬态分配；struct 键（`2644373`）反而减少了每次入账的字符串拼接分配。
4. 瞬态项：#3 之后无限速用户的连接会经过禁用限速器包装（`RateLimitedConn`，每连接约 200 B，连接关闭即释放），1000 并发连接 ≈ 0.2 MiB。
5. 低内存约束复核：无新增常驻 goroutine、无无界缓存/重试队列；增量全部随用户数有界。

## 方法论备注（复测时注意）

- **首次执行膨胀**：新构建 exe 的第一次运行工作集会虚高（页面触碰/杀软扫描），一次运行内即回落。首轮粗测曾因此出现虚假的 +16 MiB"差异"；正式数据全部在预热运行之后采集，且用同源码不同构建路径的对照（工作集 14.6 vs 14.8 MiB）排除了构建路径影响。
- 工作集用 `Get-Process WorkingSet64`；Go heap 用程序自带 `-debug-runtime-log` CSV（`/proc` 列在 Windows 为 0，heap/goroutine 列有效）。
- 强制 GC 模式（`-scavenge-every 2s`）工作集是最紧的对比口径；默认模式更接近生产行为。
